# AGENTS.md — rules for any AI agent working on Liberarr

These rules apply to every AI coding agent (Claude Code, Copilot, Codex, Cursor, …). They are binding. If a task conflicts with a rule, stop and ask the owner.

## What Liberarr is

A self-hosted, *arr-stack-inspired app that frees Plaud recordings from the vendor: audio in → reliable transcript, identified speakers, AI summaries and visuals (mind map, action table), with any AI provider. Packaged with `docker compose`, runs on a Mac then a NAS (Intel N300, no GPU).

## Architecture rules

1. **Liberarr is autonomous.** Its own DB and web UI are the source of truth. Obsidian, Plaud cloud, and any AI vendor are optional plug-ins, never hard dependencies.
2. **Sources are pluggable** (like *arr indexers): Plaud cloud, watched folder, upload, later direct device access. The pipeline never knows where audio came from.
3. **All AI calls go through one OpenAI-compatible client**, pointed at LiteLLM (or any OpenAI-compatible base URL). No vendor SDKs in app code.
4. **Pipeline steps are resumable jobs.** A failed step never deletes prior outputs. The original audio is stored untouched.
5. **Never silently change a transcript.** LLM corrections are stored as `{original, corrected, reason}`; the raw transcript is always kept and viewable.
6. **Voiceprints never leave the machine.** Diarization, speaker embeddings and matching run in the local `audio` service only. Never send embeddings to any API.
7. **Routing is per recording type**, and steps that run before auto-classification use the pre-set type or the owner's "unclassified" safe route.
8. **Obsidian export is one-way** and writes only between `%% liberarr:start %%` / `%% liberarr:end %%` markers.
9. **Portability:** state lives in `/config` and `/data`; secrets key in `.env`. Nothing machine-specific in images.
10. **Single admin user** for now. Do not build multi-user scaffolding until asked.

## Code organisation (DDD)

- **Backend**: one package per bounded context under `backend/src/liberarr/` — `recordings`, `transcription`, `summaries`, `exports`, `jobs`, `sources`, `auth` — plus `shared/` (config, db, AI client). Each context has up to four layers:
  - `domain.py`: entities, value objects, pure rules, and **ports** (`Protocol`s). No I/O, no SQL, no framework imports.
  - `application.py`: use cases (one class per use case, `run(...)`), depending only on domain ports.
  - `infrastructure.py`: adapters implementing the ports (SQLite repositories, ffmpeg, LLM/OpenAI-compatible clients, filesystem).
  - `api.py`: FastAPI routes; thin, call use cases or repositories' read models.
- Dependencies point inward: `api`/`infrastructure` → `application` → `domain`. A context may use another context's **domain** (ports/entities), never its infrastructure — except through the composition root.
- Wiring happens only in the composition roots: `container.py` (`build_services`), `app.py` (HTTP), `worker.py` (worker).
- **Frontend** mirrors the contexts: `frontend/src/features/<context>/` (API hooks, types, components), shared code in `frontend/src/shared/`.

## Stack

- Backend: Python, managed with **`uv`** (`uv add`, `uv run`; no pip/poetry). FastAPI, SQLite (FTS5 for search).
- Worker: same image as the API, different command.
- UI: **Vite** + React + TypeScript, Tailwind + shadcn/ui, TanStack Query, Mermaid. Built to static files served by the backend.
- Gateway: LiteLLM. Local audio: faster-whisper / WhisperX + pyannote.
- Transcription must handle **French with mixed English** in the same recording (multilingual models only). Summaries default to French.

## Security & privacy

- Pin exact versions of every image and dependency. Never `latest`. LiteLLM especially (2026 supply-chain incident).
- **One secrets source: the root `.env`** (gitignored, generated by `scripts/init-env.sh`). No secret value in any other file: config files reference env vars (`os.environ/VAR` in `litellm.yaml`, `${VAR}` in compose), code reads env only. `.env.example` holds names and placeholders only. Never derive a second copy of a secret by hand — interpolate it.
- Secrets the app stores itself (Plaud token, later) encrypted at rest with a key from `.env`, not from `/config`.
- No unauthenticated endpoints except health. Rate-limit login.
- Recordings include work meetings and biometric data: never log transcripts, audio paths with content, tokens, or embeddings.
- Never commit secrets, `.env`, or real recordings. Test fixtures use synthetic or owner-approved audio only.

## Agent behaviour

- **Ask before**: committing, pushing, adding a dependency, adding a compose service, changing a rule in this file, or anything touching the Plaud account.
- **Smallest complete change.** No speculative features, options or abstractions. Reuse what exists before adding.
- **Tests only for critical behaviour** (data loss, security, money, parsing untrusted output, core pipeline). No tests for trivial code or for the sake of coverage.
- **Before every push**: run the `ponytail-review` skill on the changes and fix the findings judged relevant; mention the skipped ones.
- Verify before claiming done: run the tests/build and report real output, including failures.
- Reverse engineering of the Plaud device/app is a **separate project**; do not mix it into app code. It only ever lands as a new source.
- Design docs and plans live in `docs/superpowers/` and are **never versioned** (gitignored).
- Talk to the owner in French; write code, comments, commit messages and docs in English.
